4. Step-by-Step Incident Lifecycle Workflow

1 Emergency Call Intake

Call received at central intake. Caller phone number is hashed with a secret salt (CallerHashUtil.java). Raw citizen PII is never stored (Rule #6). Incident location is saved as PostGIS Point in schema incident.

2 Multi-Factor Candidate Scoring

DispatchScorer evaluates all available ambulances. Computes turn-by-turn road travel time via GraphHopper, capability penalty for non-ALS units, and freshness penalty for stale GPS pings (>60s). Ranks best units in real time.

3 Atomic Zero-Race Reservation

Dispatcher hits "Confirm Dispatch". Database executes conditional SQL: UPDATE ambulance_unit SET status = 'DISPATCHED' WHERE id = :id AND status = 'AVAILABLE'. Eliminates double-booking bugs. Decision hashed to Merkle chain.

4 Proactive City Protection

The moment unit departs, redeployment-service runs the MEXCLP coverage algorithm. If a suburban zone drops below safety thresholds, it triggers a repositioning order for an idle unit to preserve citywide safety.

5 Live Device GPS Telemetry

Crew taps "📡 Transmit My Device Live GPS" on mobile phone (/crew/index.html). High-accuracy coordinates stream every 2s. Dispatcher map updates the ambulance marker sliding along roads toward patient.

6 Hospital ED Matching & Handover

DestinationRanker scores all receiving hospitals by road transit time, free trauma beds, and diversion states. Top hospital is pre-alerted via SSE. Paramedics complete digital handover, resetting unit status to AVAILABLE.
